1. KIẾN TRÚC MẠNG LIÊN TỈNH (CROSS-SITE TAILSCALE MESH)

Giải quyết triệt để bài toán Mini PC đặt tại TP.HCM kết nối tới camera ở Đồng Tháp và Đồng Nai mà không cần mở cổng modem (Port Forwarding):

  • Tại mỗi nhà ở quê (Đồng Tháp / Đồng Nai): Lắp 1 bo mạch Pi/TV Box chạy Armbian, kết nối LAN vào modem và cấu hình làm Tailscale Subnet Router (tailscale up --advertise-routes=192.168.x.0/24).
  • Tại Mini PC trung tâm (TP.HCM): Kích hoạt tailscale up --accept-routes. Mini PC định tuyến thẳng tới dải IP camera ở quê thông qua đường hầm mã hóa WireGuard mà không có độ trễ NAT.
2. CƠ SỞ DỮ LIỆU SQLITE TOÀN DIỆN (SCHEMA DEFINITION)
CREATE TABLE homes (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL,                         -- 'Nhà Ba Mẹ (Đồng Tháp)', 'Nhà Vợ (Đồng Nai)', 'Nhà Mình'
    telegram_chat_id TEXT NOT NULL,             -- Chat ID nhóm nhận thông báo
    subnet_cidr TEXT,                           -- '192.168.1.0/24' (quản lý qua Tailscale)
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE cameras (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    home_id INTEGER NOT NULL REFERENCES homes(id),
    name TEXT NOT NULL,                         -- 'Phòng khách', 'Sân trước'
    rtsp_main TEXT NOT NULL,                    -- rtsp://user:pass@192.168.1.50:554/stream1 (1080p)
    rtsp_sub TEXT NOT NULL,                     -- rtsp://user:pass@192.168.1.50:554/stream2 (360p)
    is_active BOOLEAN DEFAULT 1,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE ai_models (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL,                         -- 'Fall Pose v1', 'Fire Detection v1'
    model_type TEXT NOT NULL,                   -- 'pose', 'detect', 'face'
    file_path TEXT NOT NULL,                    -- '/models/yolov8n-pose.pt'
    labels TEXT,                                -- 'fall' hoặc 'fire,smoke'
    is_active BOOLEAN DEFAULT 1
);

CREATE TABLE camera_model_configs (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    camera_id INTEGER NOT NULL REFERENCES cameras(id),
    model_id INTEGER NOT NULL REFERENCES ai_models(id),
    scan_fps REAL DEFAULT 2.0,                  -- Tần số quét độc lập (Pose 3 FPS, Fire 1 FPS)
    confidence_threshold REAL DEFAULT 0.5,
    is_enabled BOOLEAN DEFAULT 1
);

CREATE TABLE users (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    username TEXT UNIQUE NOT NULL,
    password_hash TEXT NOT NULL,
    role TEXT CHECK(role IN ('admin', 'member')) NOT NULL,
    home_id INTEGER REFERENCES homes(id),       -- NULL nếu là admin, gán ID nếu là member
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE events (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    camera_id INTEGER NOT NULL REFERENCES cameras(id),
    model_name TEXT NOT NULL,
    event_type TEXT NOT NULL,                   -- 'fall_detected', 'fire_detected'
    ai_context_desc TEXT,                       -- Đoạn mô tả sinh tự động từ Gemini
    snapshot_path TEXT NOT NULL,
    video_path TEXT NOT NULL,
    timestamp DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE timelapses (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    camera_id INTEGER NOT NULL REFERENCES cameras(id),
    date_str TEXT NOT NULL,                     -- 'YYYY-MM-DD'
    video_path TEXT NOT NULL,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
3. ĐẶC TẢ CÁC MODULE XỬ LÝ LÕI BACKEND

Module 1: Pipeline RTSP & Dynamic Camera Worker (stream_worker.py)

  • Mỗi camera quản lý bởi một Worker Thread độc lập:
    • Sub-stream Worker: Đọc luồng 360p đưa vào hàng đợi AI. Tích hợp bộ lọc MOG2 (bỏ qua frame tĩnh khi biến thiên pixel < 2%).
    • Main-stream Worker: Đọc luồng 1080p nạp vào collections.deque(maxlen=150) trên RAM (5 giây bộ đệm).
  • RTSP Watchdog: Nếu 5 giây không nhận frame mới, tự động giải phóng kết nối và reconnect sau 3 giây.
  • Dynamic Add: API POST /api/cameras khởi tạo Thread mới và đăng ký sang go2rtc qua REST API (PUT /api/streams) mà không cần khởi động lại toàn bộ app.

Module 2: Dynamic Model Registry (model_manager.py)

  • Hỗ trợ kiến trúc nạp đa mô hình đồng thời trên CPU/iGPU:
    • Default Model: yolov8n-pose.pt (Quét 3–5 FPS, lọc góc xương sống < 30° + gia tốc rơi + bất động > 5s).
    • Pluggable Models: Hỗ trợ nạp động model YOLO Detect (fire.pt, face.pt) qua API upload file.
  • Mỗi camera worker duyệt danh sách model đang kích hoạt và chạy tuần tự theo chu kỳ FPS cấu hình trong DB.

Module 3: Smart Notification Engine (notifier.py)

  • Khi có sự cố (ngã / cháy):
    1. Trích xuất snapshot nét nhất từ Ring Buffer.
    2. Gọi Gemini 2.5 Flash API (Free Tier qua google-genai SDK): "Mô tả cực ngắn bối cảnh: vị trí ngã, tư thế nằm, vật dụng xung quanh". Có try/except an toàn khi rớt mạng.
    3. Ghi tiếp 10 giây video 1080p sau biến cố, ghép với 5 giây trước từ RAM tạo clip MP4 15 giây.
    4. Bắn thông báo (Ảnh Snapshot + Mô tả AI + Clip 1080p) vào telegram_chat_id của nhà tương ứng.

Module 4: Kiểm soát phiên xem đồng thời (session_limiter.py)

  • Trình duyệt khi mở WebRTC stream bắt buộc duy trì WebSocket Heartbeat: /ws/stream-session?cam_id={id}.
  • Server kiểm tra active_sessions[home_id]:
    • Nếu active_sessions < 3: Cấp luồng WebRTC và tăng biến đếm. Heartbeat định kỳ 10 giây.
    • Nếu active_sessions >= 3: Chặn người thứ 4, trả về mã lỗi ERR_SESSION_LIMIT, tuyệt đối không đá người đang xem.
  • Khi ngắt WebSocket hoặc sau 15 giây mất Heartbeat: tự động giải phóng 1 slot.

Module 5: Cơ chế phòng vệ chống tràn ổ đĩa (disk_guard.py)

Ngưỡng dung lượng Hành động tự động của hệ thống Mục tiêu bảo vệ
≥ 80% Disk Use Bắn cảnh báo Telegram cho Admin: "Ổ cứng đã dùng trên 80%". Cảnh báo sớm, không can thiệp file.
≥ 85% Disk Use Xóa cuốn chiếu (FIFO) các video Timelapse cũ nhất trước. Giữ nguyên 100% video sự kiện ngã 1080p. Hạ dung lượng tức thì mà không mất clip quan trọng.
≥ 95% Disk Use Kích hoạt Circuit Breaker: Ngắt ghi video xuống ổ cứng. Chỉ gửi clip qua Telegram và xóa ngay trên RAM. Bảo vệ hệ điều hành Ubuntu không bị sập hay rơi vào trạng thái Read-Only.
4. REST API SPECIFICATION
Method Endpoint Quyền truy cập Chức năng xử lý
POST /api/auth/login Public Xác thực username/password, trả về JWT Token chứa role và home_id.
GET /api/cameras Admin / Member Lấy danh sách camera (Member chỉ thấy camera nhà mình; Admin thấy cả 6 camera).
POST /api/cameras Admin Only Thêm camera mới: test RTSP trong 3s, spawn Worker Thread, nạp luồng sang go2rtc.
POST /api/models/upload Admin Only Tải lên file model AI mới (.pt/.onnx), đăng ký vào bảng ai_models.
GET /api/events Admin / Member Lấy danh sách clip sự kiện ngã/cháy kèm phân tích AI theo ngày và nhà.
GET /api/timelapses Admin / Member Lấy danh sách video timelapse 1 ngày theo nhà và bộ lọc thời gian.
GET /api/system/metrics Admin Only Trả về thông số phần cứng Mini PC: % CPU, % RAM, % Ổ cứng, Nhiệt độ.
5. TỰ ĐỘNG HÓA VẬN HÀNH (SYSTEMD & CRONJOB)
# 1. Cấu hình dịch vụ Systemd tự hồi sinh: /etc/systemd/system/camera-ai.service
[Unit]
Description=Smart Edge AI Camera Service
After=network.target tailscaled.service

[Service]
Type=simple
User=root
WorkingDirectory=/opt/camera-ai
ExecStart=/opt/camera-ai/venv/bin/python main.py
Restart=always
RestartSec=5s

[Install]
WantedBy=multi-user.target

# 2. Các Cronjob bảo trì tự động: crontab -e
# Render video Timelapse mỗi đêm lúc 23:59
59 23 * * * /opt/camera-ai/venv/bin/python -m scripts.render_timelapse
# Tự động xóa file video cũ quá 90 ngày lúc 02:00 sáng
00 02 * * * find /opt/camera-ai/storage/ -type f -mtime +90 -delete
# Khởi động lại service lúc 03:00 sáng Chủ Nhật để xả sạch RAM leak
00 03 * * 0 /bin/systemctl restart camera-ai.service
